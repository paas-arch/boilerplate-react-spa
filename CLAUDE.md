# CLAUDE.md

Инструкции для ИИ-агента, который дописывает это веб-приложение. Язык интерфейса, текстов для людей и общения — русский.

## Что это

Веб-приложение на React, созданное из шаблона `react-web` панели paas. Панель собирает его в образ и выкатывает на сервер рядом с бэкендом проекта. Код — твой: пиши свои страницы. Пример в шаблоне — страница заметок, которая ходит в бэкенд из шаблона `go-backend`: замени её своей.

Стек: React 19, TypeScript, Vite, React Router, TanStack Query, Tailwind CSS 4, компоненты shadcn/ui, React Hook Form и Zod, Vitest и Testing Library. Код разложен по Feature-Sliced Design: `app` → `pages` → `features` → `entities` → `shared`; импорт идёт только вниз, через `index.ts` слоя, с алиасом `@/`.

## Договор с панелью — не нарушай

Панель выкатывает приложение, не читая код, по этим соглашениям. Если их сломать, сборка или выкатка упадёт.

- **`.paas/template` и `CHANGELOG.md` — метки шаблона.** `.paas/template` хранит версию шаблона, из которой код приложения; её ставит панель, и по ней она предлагает обновление PR-ом. Не правь её руками. `CHANGELOG.md` — что нового в версиях шаблона.
- **`paas.toml` — настройки приложения на сервере.** Число копий и размер задаёт только этот файл; панель читает его при раскатке. Неизвестный ключ — ошибка: сборка проверяет файл и с ошибкой не соберёт версию. `name` не меняй: он равен имени репозитория. Пояснения — комментарии в самом файле.
- **Не меняй `Dockerfile`, `Caddyfile` и `.github/workflows/release.yml`.** По ним каждый пуш в `main` собирает образ `ghcr.io/<организация>/<репо>/web` с тегом версии.
- **Запросы к бэкенду — только по относительным путям `/api/...`.** В образе всё под `/api/` пересылается бэкенду проекта; адрес бэкенда панель передаёт при запуске. Не вшивай адрес бэкенда в код и не заводи для него переменные `VITE_*`: они попадают в сборку, и смена адреса потребовала бы новой версии.
- **Адреса страниц не должны начинаться с `/api` и быть `/health`.** `/health` отвечает панели, что приложение запущено.
- **Сборка — `yarn build` в `dist/`.** Не меняй команду и папку: образ берёт файлы оттуда.
- Секретов во фронтенде нет: всё, что попало в сборку, видно любому посетителю. Ключи внешних сервисов держит бэкенд.

## Связь с бэкендом

Типы клиента API собираются из `api/backend-schema.yaml` — копии контракта бэкенда (`api/schema.yaml` в его репозитории). Бэкенд поменял контракт — скопируй его файл сюда целиком и выполни `yarn api:generate`; результат в `src/shared/api/generated/` закоммить, CI проверяет, что он свежий. Запросы — через `apiRequest` из `@/shared/api`: ошибка бэкенда приходит как `ApiError` с текстом для человека, показывай его как есть.

## Команды

- `cp .env.example .env.local && yarn install && yarn dev` — разработка на http://localhost:5173; `/api` уходит на `BACKEND_URL` из `.env.local`.
- `yarn test`, `yarn lint`, `yarn format:check`, `yarn build` — то же проверяет CI. `make check` запускает всё сразу.
- `yarn api:generate` — типы клиента API после правки `api/backend-schema.yaml`.
- Компоненты shadcn/ui добавляются командой `npx shadcn@latest add <компонент>` в `src/shared/ui`.

## Правила кода

- Серверные данные — только через TanStack Query: ключи в `entities/<сущность>/api`, после изменения — `invalidateQueries` по этому ключу.
- Формы — React Hook Form и схема Zod в `features/<фича>/model`; ограничения те же, что проверяет бэкенд.
- Тесты — Vitest и Testing Library, запросы подменяются через `vi.stubGlobal('fetch', ...)`; пример — `src/app/App.test.tsx`.
- Комментарий — одна строка и объясняет «почему».
- Возникли вопросы по задаче — задавай их человеку по одному.
