# react-web

Шаблон веб-приложения на React для сервисов [paas](https://github.com/paas-arch/paas). Панель создаёт из него репозиторий в организации клиента; клиент дописывает код, а панель собирает и выкатывает приложение рядом с бэкендом проекта.

В шаблоне:

- страница-пример «Заметки», которая читает и пишет данные через бэкенд из шаблона `go-backend`;
- клиент API с типами из контракта бэкенда (`api/backend-schema.yaml`);
- образ на Caddy: раздаёт сборку, отвечает на `/health` и пересылает `/api/*` бэкенду, адрес которого приходит при запуске;
- сборка образа в GHCR на каждый пуш в `main` и проверки (линтер, форматирование, тесты, сборка) на каждый PR;
- инструкции для ИИ-агента в `CLAUDE.md`.

Входа пользователей и предметного кода нет.

## Локальный запуск

Нужны Node.js 22 и Yarn 1. Бэкенд из шаблона `go-backend` — на `:8080` (`make run` в его репозитории).

```sh
cp .env.example .env.local
yarn install
yarn dev    # http://localhost:5173
```

## Договор с панелью

Что нельзя менять, чтобы панель могла собрать и выкатить приложение, — в `CLAUDE.md`, раздел «Договор с панелью». Решение и его причины — ADR-0008 в репозитории paas.

## Образ

| Переменная    | Назначение                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `APP_PORT`    | Порт, по умолчанию 8080. На сервере задаёт панель                                                                                  |
| `BACKEND_URL` | Адрес бэкенда для `/api/*`, например `http://api.shop`. На сервере задаёт панель; без него `/api` отвечает 502, остальное работает |

## Версии шаблона

Версия шаблона — тег git `vX.Y.Z` этого репозитория. Панель копирует в новый репозиторий выбранную версию и запоминает её у сервиса.
